# PlayLog

Track every game you play: hours, S–E ratings, platforms and backlog, in one dark, loud dashboard.

**Stack:** Next.js (App Router) · TypeScript · Tailwind CSS v4 · Supabase (Postgres + Storage) · Auth.js (NextAuth v5) with Google sign-in.

## Setup

### 1. Install

```bash
npm install
```

### 2. Supabase

1. Create a project at [supabase.com](https://supabase.com).
2. Open the **SQL editor** and run the contents of [`supabase/schema.sql`](supabase/schema.sql). This creates the `games` table (RLS locked) and the public `game-images` storage bucket.
3. From **Project settings → API**, copy the **Project URL** and the **service_role key**.

### 3. Google OAuth

1. In [Google Cloud Console](https://console.cloud.google.com/apis/credentials), create an **OAuth client ID** (type: Web application).
2. Add the authorized redirect URI:
   - Dev: `http://localhost:3000/api/auth/callback/google`
   - Prod: `https://your-domain.com/api/auth/callback/google`
3. Copy the client ID and secret.

### 4. Environment

Copy `.env.example` to `.env.local` and fill it in (a `.env.local` with placeholders and a generated `AUTH_SECRET` is already present):

| Variable | What it is |
|---|---|
| `AUTH_SECRET` | Random secret for Auth.js (`npx auth secret`) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google OAuth credentials |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service role key (server-only) |
| `NEXT_PUBLIC_SITE_URL` | Canonical URL used for SEO/sitemap |

### 5. Run

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## How it's wired

- **Auth**: Auth.js v5 with the Google provider and JWT sessions (`src/auth.ts`). `src/middleware.ts` guards `/dashboard`; API routes check the session themselves. On every sign-in the Google profile (id, email, name, avatar, last sign-in time) is upserted into `public.users`.
- **Data**: API routes (`src/app/api/games`, `/api/upload`) use the Supabase **service role** key server-side and scope every query to the signed-in user's id. RLS stays enabled so the public anon key has no table access.
- **Images**: uploaded via `/api/upload` into the public `game-images` bucket (stored per-user, max 5 MB), or set directly by pasting an image URL, either way saved as the game's `image_url`.
- **Share pages**: from the dashboard, a user can turn on a public backlog page (`/u/[id]/backlog`) and/or a public completed-games tier list (`/u/[id]/tier`). Both default to off and are toggled via `/api/settings`, which flips `backlog_public`/`tier_public` on `public.users`.
- **SEO**: only the landing page (plus privacy/terms/contact) is indexable. `/dashboard` and `/u/` are `noindex` and disallowed in `robots.txt`; sitemap and robots are generated by `src/app/sitemap.ts` and `src/app/robots.ts`.
